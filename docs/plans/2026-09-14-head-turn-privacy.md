# HeadUp 转头屏幕保护实现规划

状态：核心功能已实现并纳入 0.3.0。
日期：2026-09-14

## 目标与范围

在现有 macOS 菜单栏应用中增加独立的「屏幕保护」功能：戴着兼容 AirPods，头部朝向离开校准后的二维工作范围，所有屏幕自动模糊；回到范围内后恢复。多屏用户可以校准不对称的左右边界，也能设置仰头、低头边界。遮挡层可展示系统日期、时间、天气和自定义文字。

保留现有低头提醒、统计、通知和开机启动。新功能默认关闭，首次主动启用时引导校准。它判断头部方向，不判断眼球视线；不是系统锁屏，也不承诺阻止截图、录屏或屏幕共享。第一版不加入应用白名单、根据朝向逐屏显隐。

## 用户体验与建议默认值

### 校准与多屏范围

1. 提示坐在日常工作位置、戴好耳机，并确认正在收到新鲜姿态样本。
2. 正视主要屏幕，稳定采样约 2 秒，作为中心。
3. 看向正常工作时最左的位置，稳定采样约 1 秒；再采集最右位置。不要求左右对称。
4. 分别看向正常工作区的最高、最低位置，采集仰头与低头边界。
5. 展示实时角度和四向允许区间，支持单独调整左右、上下边界。
6. 试着在屏幕之间切换，再向任一范围外转头，预览遮挡效果后保存。

左/右范围建议分别限制为离中心 5°–85°，上/下范围限制为 5°–60°，最终范围和稳定性阈值以硬件验证为准。边界来自实际头部动作，不根据显示器像素排列推算物理角度。不自动扩大允许范围，也不在使用中偷偷重设中心。

保存左右宽度、设置版本和显示器布局标识；绝对中心只对当前运动会话有效。耳机重连、运动 manager 重建、应用重启、唤醒后要求快速正视校准中心；布局改变要求复核左右边界。不能假定旧 yaw 零点跨会话稳定。

### 触发与恢复

| 设置 | 建议初始值/行为 |
| --- | --- |
| 转开多久后遮挡 | 0.8 秒，可调 0.2–3 秒 |
| 回正多久后恢复 | 0.3 秒，可调 0.1–2 秒 |
| 边界缓冲 | 3°；恢复时需进入比触发区间更窄的范围，避免闪烁 |
| 保护屏幕 | 全部已连接显示器，使用完整 `frame`，覆盖桌面边缘 |
| 低头看键盘 | 纳入向下边界；默认范围比向上更宽，用户按日常工作姿势校准 |
| 临时暂停 | 菜单栏和遮挡层按钮，显式恢复后重新布防 |
| 紧急解除 | 可配置全局快捷键；解除后进入暂停，避免立即重新遮挡 |
| 首次缺少权限/耳机 | 显示未启用原因，不在首次启动直接盖住屏幕 |

全局快捷键注册失败必须显示冲突并允许修改；遮挡层始终有清晰的「暂停保护」按钮作为独立恢复入口。遮挡期间拦截鼠标点击，不允许点到下面的文档；第一版不承诺阻断所有键盘输入，也不使用广泛键盘监听实现锁屏。

### 断连和异常

- 只有已经完成校准并进入布防状态后，才应用数据失效策略。
- 默认数据失效时进入或保持纯色遮挡，显示原因及手动解除按钮；设置中可改为退出遮挡并暂停保护。
- 失效包括断连、权限失效、样本冻结、manager 重建；用独立定时检查发现停流，不能依赖下一帧到来。
- 建议超过 1 秒无新传感器样本视为失效，实测调整；传感器恢复后重新确认中心，不用旧角度自动解开。
- 已布防时显示器变化，立即覆盖新增屏幕，并进入待重新校准；已有遮挡保持。未布防时仅更新提示。
- 系统锁屏/睡眠时暂停判定和动画，唤醒后等待有效数据与中心校准；不得覆盖系统登录认证界面。
- 低头提醒因走路/跑步暂停时，不能顺带关闭隐私保护。手动关闭保护或退出应用必须清理全部覆盖窗口和快捷键。

### 遮挡内容

- 日期、时间独立开关，默认开启；跟随系统语言、时区和时间格式，可选秒数。调整系统时间不影响保护延迟计时。
- 自定义纯文字，默认关闭；支持多行、字号、颜色，建议最多 200 字，预览超长文字和小屏布局。不支持 HTML 或执行模板。
- 天气默认关闭，用户手动搜索并选择城市，不申请定位权限；显示天气图标、温度和城市，可切换温度单位。
- 信息默认只显示在主屏，其他屏幕保持遮挡；可选全部屏幕显示相同内容。
- 设置页提供局部预览及可退出的全屏测试；无需耳机即可预览外观，测试退出后恢复原有状态。

## 技术方案与前置验证

### 1. 四向运动与共享服务

建议新增 `HeadphoneSessionCoordinator` 统一管理现有 motion/activity 服务，按「姿态提醒启用 OR 屏幕保护启用 OR 正在校准」决定运动采集需求。避免创建两个 manager，也避免一个 store 覆写另一个的单回调。

`MotionSample` 增加 yaw、传感器单调时间、session ID；保留 Date 用于已有历史统计。当前轮询每次用 `Date()` 包装最新姿态，即使底层仍是同一帧也会被当成新样本；需要按底层 timestamp 去重，并只在真实新帧到来时重置看门狗。

水平角差按圆周规范化到 [-180°, 180°)，校准用圆周统计，不能直接平均跨 ±180° 的角度。校准必须验证新鲜度、样本数量、稳定性、左右顺序和最小范围；失败时保留设置，不能保存半份校准。先验证相对 yaw；若坐姿倾斜时误差明显，再考虑四元数相对姿态计算，不能凭算法替代硬件验证。

### 2. 纯状态机与覆盖窗口分离

建议 `PrivacyAnalyzer` 作为无 AppKit 依赖的状态机，输入样本、设置、会话事件和单调时间；`PrivacyStore` 负责 UI 状态及协调覆盖层。

状态建议为：`disabled`、`needsCalibration`、`calibrating`、`watching`、`pendingHide`、`covered`、`pendingReveal`、`paused`、`trackingLost`。数据失效状态另带是否保持遮挡的策略结果。

`watching → pendingHide → covered` 必须连续超出边界；中途回来取消计时。`covered → pendingReveal → watching` 必须持续进入收窄的恢复区；离开恢复区则回到 covered。关闭、暂停、会话变化、设置变化均明确重置待触发计时。显示层只响应状态转换，不随每帧反复创建窗口。

### 3. 多屏模糊不能提前当作已解决

新增 `PrivacyOverlayController`，按显示器 ID 管理覆盖窗口，使用 SwiftUI 展示信息，AppKit 控制层级、Space 和鼠标事件。先做可手动开关的技术验证：多个分辨率/缩放比例、原生全屏应用、Space 切换、热插拔、Stage Manager、菜单栏和 Dock。现有 `.floating` HUD 不足以证明全屏覆盖可靠。

优先验证 `NSVisualEffectView` 的 behind-window 材质。Apple 文档说明该模式使用窗口后方内容混合，但没有保证能提供任意强度的全桌面高斯模糊；不直接承诺「模糊半径滑块」。可确定提供的是压暗强度及纯色模式。原生材质效果、降低透明度设置下的行为、是否仍能辨认文字均需实测。

若原生材质无法满足实际模糊效果，再验证 ScreenCaptureKit 捕获并模糊的方案：需要屏幕录制授权，过滤自身覆盖窗口，处理权限拒绝、受保护内容、显示器重配和性能。只在内存处理画面、不落盘或上传。先验证模糊静态快照能否满足用户体验，若必须动态画面再评估低帧率流。捕获等待或失败期间使用纯色层，不暴露未处理的图像。

**验收门槛：真实模糊必须有可运行证据。纯色是异常回退和可选模式，不能悄悄替代用户要求的模糊。** 第一阶段验证后记录最终渲染路径及是否需要新增权限；当前不声称已完成该验证。

### 4. 天气是独立可失败功能

新增 `WeatherProviding` 接口和 `WeatherService`；供应商选择放在天气任务开始时核验，比较城市搜索、国内可达性、使用许可、署名、调用限额、密钥与发行方式，记录选择依据。不能将需付费账号或私有密钥的服务当作已有条件。

建议启用后按 30 分钟刷新、共用多屏缓存；关闭天气时停止请求。缓存最近结果及更新时间，超过 2 小时显示过期提示，失败时显示暂无天气，不影响遮挡或时钟。测试通过注入假供应商完成，不依赖真实网络。

天气仅发送查询城市/坐标及供应商协议必要字段，不发送头部姿态、自定义文字或屏幕内容。修改 `PRIVACY.md` 中「无网络客户端」的承诺，设置中注明供应商及联网用途。供应商无法满足发行条件时明确列为未完成项，不能用占位天气算交付。

## 最终验收矩阵

- 自动化：保留全部旧测试；增加角度环绕、非有限输入、校准稳定性、延迟/迟滞、会话失效、时间跳变、设置迁移、天气缓存和协调器生命周期测试。UI 布局不写机械镜像测试。
- 真机姿态：主屏/左屏/右屏正常切换、短暂转头、长时间转开、低头打字、侧倾、重新佩戴、持续办公 30 分钟；记录耳机型号和系统版本。
- 显示器：单屏、双屏、不对称布局、不同缩放、负坐标屏幕、原生全屏、Space 切换、热插拔、显示器休眠唤醒；三屏有条件补测，无硬件时明确未覆盖。
- 故障：无运动权限、耳机断连、冻结旧帧、manager 重建、系统锁屏、天气离线、快捷键冲突；每种情况均有可见原因和退出路径。
- 外观：浅色/深色、降低透明度、降低动态效果、大字敏感内容、多行文字、日期跨天；模糊模式实际效果与描述一致。
- 回归：已有低头两步校准、运动中暂停提醒、通知/HUD、每日统计、历史、设置窗口、开机启动均不被新功能破坏。
- 性能：对比保护关闭、已布防、遮挡三种状态的 CPU/内存；窗口不随采样重建，时钟和天气更新不触发连续屏幕捕获。记录数据后决定是否需要优化。
- 命令：`swift test`、`swift build`；真机验收时执行 `./script/build_and_run.sh --verify`。注意现有脚本会结束正在运行的 HeadUp 并重建本地 app，不在本次纯文档规划中执行。

## 待验证与审阅事项

建议直接采用：功能默认关闭、全屏同时保护、五步四向校准、内容默认仅主屏、天气可选联网、断连默认保持遮挡并允许手动退出。

实施前段必须解决的技术问题：实际 yaw 稳定性、模糊渲染路径及授权需求、原生全屏覆盖和恢复快捷键可靠性。天气供应商及使用条件在天气任务开始前确定。上述未知项不阻止先完成本规划，也不应被描述为已验证能力。
